# 스레드·인스타 전략과 자동화 분석

작성: 2026-07-31 · 목표: 후쿠오카 출발(10/25) 전에 첫 유료 사용자 확보

---

## 1. 결론 세 줄

1. **자동 게시는 기술적으로 된다.** 스레드·인스타 둘 다 공식 API 로 글을 올릴 수 있다.
2. **그런데 지금 하면 안 된다.** 지금 병목은 "올리는 수고"가 아니라 "올릴 내용"이다.
3. **자동화할 것은 게시가 아니라 콘텐츠 생산이다.** 앱이 만든 동선·지도·기록을
   그대로 게시물 소재로 뽑아내는 쪽이 값이 크고, 그건 내가 앱 기능으로 만들 수 있다.

---

## 2. 자동 게시 — 기술 검토

> ⚠️ 아래는 2026년 5월 기준으로 알고 있는 내용이다. 이 작업 환경은 외부 접속이
> 막혀 최신 문서를 확인하지 못했다. **실제로 붙이기 전에 공식 문서를 다시 볼 것.**

### 스레드 (Threads API)

| 항목 | 내용 |
| --- | --- |
| 공식 지원 | 있다 (2024년 공개) |
| 가능한 것 | 글·이미지·동영상·캐러셀 게시, 답글 조회, 인사이트 |
| 필요한 것 | Meta 개발자 앱 + 액세스 토큰 |
| 제한 | 하루 게시 수 상한이 있다(수백 건 수준) |
| 걸림돌 | 토큰이 **약 60일마다 만료** → 갱신할 서버가 필요하다 |

### 인스타그램 (Instagram Graph API)

| 항목 | 내용 |
| --- | --- |
| 공식 지원 | 있다 |
| 조건 | **비즈니스 또는 크리에이터 계정**이어야 하고 페이스북 페이지 연결 필요 |
| 가능한 것 | 피드·릴스·스토리 게시 |
| 걸림돌 | 일부 권한은 **Meta 앱 심사**를 통과해야 한다. 이게 며칠~몇 주 걸린다 |
| 못 하는 것 | 개인 계정 자동 게시는 안 된다 |

### 그래서 필요한 것

둘 다 **토큰을 보관하고 갱신할 서버**가 있어야 한다. 지금 이 앱은 서버가 없다
(그게 강점이다). 자동 게시를 붙이려면 그 원칙을 깨거나, 별도의 작은 서버를 하나 둬야 한다.

**Cloudflare Workers 무료 등급이면 충분하다.** 다만 그건 "만들 수 있다"는 얘기고,
"지금 만들 값이 있다"는 얘기는 아니다.

---

## 3. 왜 지금은 하면 안 되는가

### 계산해 보면 답이 나온다

- 목표: 베타 10명
- 하루 1개씩 3개월 = 90개 게시물
- **90개를 손으로 올리는 데 드는 시간: 하루 5분 × 90일 = 7.5시간**
- 자동화 만드는 데 드는 시간: Meta 앱 등록 + 심사 대기 + 서버 + 토큰 갱신 = **최소 20시간**

**자동화가 손해다.** 게시 수가 하루 3개를 넘고 몇 달을 계속할 때부터 이익이 된다.

### 더 중요한 이유

스레드·인스타는 **답글과 반응**이 노출을 만든다. 예약 발행만 걸어놓고 답글을
안 달면 그냥 안 퍼진다. 초반에는 오히려 **손으로 올리고 손으로 답글 다는 게** 낫다.

그리고 첫 20개쯤 올려봐야 **뭐가 먹히는지** 안다. 먹히는 형식을 모른 채
자동화하면 안 먹히는 걸 자동으로 많이 올리게 된다.

---

## 4. 대신 자동화할 것 — 앱이 콘텐츠를 만들게 한다

이게 진짜 답이다. 형님이 앱을 쓰면 **게시물 소재가 자동으로 쌓인다.**

### 만들 것: 공유 카드 (내가 만든다)

앱 안에 **`📤 공유 카드 만들기`** 버튼. 누르면 그 날의 결과가 한 장의 이미지가 된다.

```
┌─────────────────────────┐
│  하카타 한 바퀴          │
│  ─────────────────      │
│  [지도 + ①②③④ 동선]    │
│                          │
│  ① 우동 타이라           │
│  ② 커피 카운티           │
│  ③ 쿠시다 신사           │
│  ④ 나카스 포장마차       │
│                          │
│  도보 47분 · 12,400엔    │
└─────────────────────────┘
```

- 이미 있는 것으로 다 만들 수 있다: 지도 SVG, 동선, 예산, 방문 기록
- 캔버스로 그려서 이미지로 저장 → **사진첩에 저장 → 인스타에 바로 올림**
- 외부 라이브러리 필요 없다
- **덤으로 이게 앱의 판매 포인트가 된다.** "여행 정리해서 자랑하는 기능"

**게시는 손으로, 소재는 자동으로.** 이게 지금 단계의 정답이다.

## 5. 뭘 올릴 것인가

### 원칙: 앱을 광고하지 말고 결과를 보여준다

> ❌ "제가 만든 여행 앱입니다"  → 아무도 안 본다
> ⭕ "구글맵에 137곳 저장해놨는데 뭘 가야 할지 모르겠다"  → 사람들이 본다

**137곳 저장해놓고 정작 못 가는 건 형님만의 문제가 아니다.** 그게 공감의 지점이다.

### 시기별로

**8월 — 문제를 보여주는 시기 (앱 언급 X)**

| 형식 | 예시 |
| --- | --- |
| 공감 | "구글맵 저장 137곳. 지난 여행에서 실제로 간 곳 6곳. 나만 이런가" |
| 목록 | "후쿠오카 저장 목록 정리하다 발견한 것 — 절반이 같은 동네" |
| 질문 | "저장은 열심히 하는데 왜 안 가게 될까" |

목표: **저장만 하고 못 가는 사람들**을 모은다. 그게 나중에 살 사람이다.

**9월 — 만드는 과정을 보여주는 시기 (앱 등장)**

| 형식 | 예시 |
| --- | --- |
| 과정 | "그래서 직접 만들었습니다. 저장한 곳 중 안 가본 곳만 골라서 동선 짜주는 것" |
| 화면 | 지도에 ①②③④ 뜬 화면 캡처 |
| 실패담 | "AI한테 코스 짜라고 했더니 없는 가게를 만들어냈다. 그래서 이렇게 막았다" |

**여기서 베타 모집.** "후쿠오카 가시는 분 10명, 만원에 드립니다"

**10월 — 실제로 쓰는 시기 (가장 강력)**

| 형식 | 예시 |
| --- | --- |
| 실시간 | 후쿠오카 현지에서 오늘 동선 캡처 + 실제 사진 |
| 비교 | "앱이 짜준 순서 vs 실제로 간 순서" |
| 결과 | "3일 동안 21곳. 저장만 해뒀던 곳들" |

**11월 — 정리하고 파는 시기**

- 다녀온 전체 기록 정리
- "이렇게 만들었습니다" 회고
- 정식 판매

### 형식 비중

- **스레드**: 글 중심. 위 문구들을 그대로. 하루 1개
- **인스타**: 이미지 중심. 지도 캡처, 음식 사진, 공유 카드. 주 3~4개
- **릴스**: 여행 중에만. 동선대로 걷는 영상 15초

## 6. 절대 하지 말 것

- **팔로워 사기·품앗이** — 반응 없는 팔로워는 노출을 오히려 깎는다
- **같은 글 여러 계정에 복붙** — 스팸으로 잡힌다
- **앱 링크를 매 글마다** — 프로필에만 두고 글에는 안 넣는다
- **플롯라인 화면·문구 인용** — 법적 경계다 (34절). 우리 화면만 쓴다

## 7. 순서

1. **지금**: 계정 만들고 8월 콘텐츠 20개를 미리 써둔다 (올리진 않고 쌓아둠)
2. **내가 할 것**: 공유 카드 기능 만들기
3. **8월**: 하루 1개씩 올리며 뭐가 먹히는지 본다
4. **9월**: 먹히는 형식으로 베타 모집
5. **자동화는 그 다음.** 하루 3개 이상 올리게 되고, 먹히는 형식을 알고,
   그때도 시간이 부족하면 그때 만든다
