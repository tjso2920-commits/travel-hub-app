# 변경 후 검수 체크리스트

## 자동 검사

```bash
npm run verify
```

- 모든 인라인 JavaScript 구문 통과
- 정적 DOM ID 중복 없음
- 개인용/판매용 `SALE_MODE`와 prefix 분리
- 원본 `:root`, `V`, `personalDays()` 보호 해시 유지
- 기준 localStorage 키 삭제 없음
- 운동 영상·편집·Gemini·영상 그룹 함수 유지
- 일본어 90팩·문법 교재·루비·발음·연계 기능 토큰 유지
- 개인용 운동2·달력 키 유지
- 개인용 고정밀 GPS 옵션 유지
- 판매용에서 운동2·실시간 GPS 제외

## 실제 화면

```bash
npm run preview
```

개인용 `http://localhost:4173/`, 판매용 `http://localhost:4173/sales.html`을 각각 확인한다.

- 첫 화면이 검은 화면이 아니며 체크인/온보딩 또는 폴백이 보인다.
- 홈 버튼이 모듈 선택 화면을 열고 기존 입력·세트를 초기화하지 않는다.
- 모든 상단 탭이 열리고 활성 표시가 한 개만 남는다.
- 모바일 폭에서 탭 간격이 일정하고 가로 넘침이 의도대로 스크롤된다.
- 운동 세트, 영상 링크, 편집, 대체 그룹, Gemini 버튼이 기존과 동일하게 동작한다.
- 운동2의 필수/보너스 세트, 상한, 영상, 달력 스냅샷이 동작한다.
- 일본어 DAY 이동, 완료, 하루 2~3팩, SRS, 루비, 히라가나, 한글 발음, 뜻, 문법 표, 듣기가 보인다.
- 달력 날짜 상세에서 기존 운동·운동2·일본어가 구분된다.
- 후쿠오카 가져오기, 필터, 선택, 영상 그룹, 지도 링크가 동작한다.
- 개인용 GPS 권한 허용/거부/타임아웃/중지와 정확도 표시를 확인한다.
- 판매용에 운동2와 실시간 GPS 제어가 보이지 않는다.
- 개발자 도구 콘솔에 앱 출처 오류가 없다.

## 데이터 호환

- 수정 전 JSON 백업을 수정 후 앱에서 불러온다.
- 기존 localStorage 데이터로 앱을 열어 운동·기록·식단·달력·일본어·후쿠오카 데이터가 남는지 확인한다.
- 새 필드가 없는 과거 데이터에서도 기본값으로 정상 동작한다.
- 개인용과 판매용을 같은 브라우저에서 번갈아 열어 데이터가 섞이지 않는지 확인한다.
- 전체 초기화나 키 마이그레이션은 사용자의 명시적 승인 없이 실행하지 않는다.

## 판매용 개인정보

- 사용자 이름, 신체·근무 정보, 여행일, 호텔, 실시간/저장 위치, 위치 이력, 개인 메모, API 키가 소스 기본값에 없는지 검색한다.
- 장소 팩은 공개해도 되는 장소 정보만 포함하는지 행 단위로 확인한다.
- 판매자 공용 Gemini·Places·YouTube 키를 넣지 않는다.
- 구매자의 로컬 데이터가 내보내기 파일이나 배포 자산에 섞이지 않았는지 확인한다.

## 납품

- 변경 전 “추가·수정 / 미변경” 설명을 했는지 확인한다.
- 부분 코드가 아니라 전체 HTML을 제공한다.
- 바뀐 소스로 개인용/판매용 다운로드 ZIP을 다시 만들고 ZIP 내부 해시를 비교한다.
- 누적 인수인계 문서 끝에 변경·미변경·검증·남은 작업을 기록한다.
- 사용자가 요청하면 실시간 검수 URL도 같은 전체 HTML로 갱신한다.
