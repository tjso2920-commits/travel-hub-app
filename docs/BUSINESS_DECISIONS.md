# 사업 결정 정리 (travel hub) — ChatGPT 판단용

작성: 2026-09-10 · 이 문서는 가격·브랜드·제품 범위를 **정하지 않는다**.
정할 수 있는 재료(확인된 사실 / 확인 안 된 가설 / 비용 구조 / 결정이
필요한 선택지)를 한곳에 모으는 것이 목적이다. 숫자를 지어내지 않는다
— 확인 안 된 값은 "모른다/확인 필요"라고 그대로 적는다.

## 1. 확인된 사실 (실제로 코드를 돌려서 검증함)

- 구글맵 저장 목록 내보내기(Google Takeout) ZIP/CSV/JSON을 실제로
  읽어 장소를 가져온다. 검증: `scripts/test-zip-import.mjs` 등.
- 가져온 장소를 도시별로 나누고, 유형(카페·맛집 등)을 짐작하되 사람이
  직접 고치면 그 선택을 유지한다.
- 걸어서 도는 코스를 만든다. 실제 도보 경로 계산(OSRM)이 되면 그
  경로를, 안 되면 방문 순서만 정직하게 대체로 보여준다 — 성공한 척
  하지 않는다. 이 샌드박스에서는 `router.project-osrm.org`로 나가는
  네트워크 요청이 막혀 있어 **이 세션 안에서는 실제 성공 응답을 한 번도
  못 받아봤다** — 로직·파라미터는 OSRM 공식 문서 기준으로 맞게
  고쳤지만, 실제 인터넷 환경에서의 성공률은 검증되지 않은 상태다.
- 서버(계정·세션·코스 저장·무료체험 1회 제한·결제 웹훅 서명 검증)는
  전부 실제 코드로 구현되고 실제 HTTP 요청으로 테스트했다 — 단,
  실제 운영 계정(호스팅·PG·이메일 발송)에는 아직 연결 안 됨(전부
  테스트 모드). 자세한 내용: `server/README.md`.
- 이메일·소개 페이지 사전 신청(`waitlist`)도 실제로 서버까지 붙어
  동작한다 — 단, 실제 이메일 발송 계정이 없어 로그인 코드는 테스트
  기록만 남고 실제로 발송되지는 않는다.

## 2. 확인 안 된 가설 (숫자·주장을 만들지 않음)

- **"9,900원/30일"은 여전히 가설 가격이다.** 코드(`server/config.mjs`)
  기본값일 뿐 확정이 아니다. 자동결제 기본값은 꺼짐.
- 이 문제(구글맵 저장 목록 정리 못 함)를 겪는 사람이 실제로 몇 명인지,
  돈을 낼 의향이 있는 비율이 얼마인지 — 데이터 없음. 검증 계획은
  `MARKETING_LAUNCH_PLAN.md` 4절(초기 체험단 5~10명) 참고.
- OSRM 실제 성공률(위 1절 참고) — 실제 인터넷 환경에서 다시 확인
  필요.
- **179건 실제 Google Takeout 데이터셋 재실행 요청 — 이번 세션에서는
  차단됨(블로킹)**: 이 샌드박스에는 그 실제 파일이 없다(검색해서
  확인함). 최종 병합 로직 기준으로 다시 돌려 보려면 사용자가 그 파일을
  다시 올려줘야 한다 — 그 전까지 "이전 실행에서 나온 숫자가 지금도
  그대로 맞다"고 가정하지 않는다.

## 3. 비용 구조 — 무엇이 비용을 만드는가 (실제 금액은 공식 가격표 확인 필요)

아래는 "무엇을 쓰면 돈이 드는가"를 정리한 것이지, 실제 단가를
지어내지 않는다. 계약 전에 반드시 해당 서비스의 **현재** 공식
가격표를 다시 확인해야 한다(요금제는 자주 바뀐다).

| 항목 | 무료로 가능한 범위 | 유료로 전환되는 조건 | 확인해야 할 곳 |
|---|---|---|---|
| 장소 조회(정확한 좌표·이름 확인) | 테스트 어댑터(가짜 좌표)로는 무료 | 실제 Google Places API 키 연결 시 요청 건수에 따라 과금 | Google Places API 공식 가격표(요청 시점에 재확인) |
| 장소 사진 | 지금은 사용자가 가져온 원본 사진만 사용, 별도 사진 API 호출 없음 | 앞으로 사진을 API로 보강하면 그때부터 과금 | 해당 시점 결정 사항(4절 참고) |
| 도보 경로 계산 | 지금은 공개 무료 OSRM 데모 서버(`router.project-osrm.org`) 사용 | **이 데모 서버는 소규모 테스트용으로만 열려 있고, 실 사용자 트래픽 규모의 상시 운영에 쓰라고 만들어진 게 아니다** — 실제 사용자가 늘면 자체 OSRM 서버를 직접 호스팅하거나 유료 라우팅 API(Google Directions 등)로 옮겨야 한다 | OSRM 프로젝트 공식 사용 정책 + 선택한 대안 서비스의 가격표 |
| 서버 호스팅(계정·코스 저장·결제 검증) | 없음 — 지금은 개발자 로컬에서만 실행됨 | 실제로 켜는 순간부터 최소한의 서버 호스팅비 발생(트래픽에 따라 증가) | 선택할 호스팅사의 가격표 |
| 결제(PG) | 없음(테스트 시뮬레이션만) | 실제 결제 연동 시 PG사 거래 수수료 발생(보통 결제 건당 정률+정액) | 선택할 PG사 가맹 조건 |
| 이메일 발송(로그인 코드) | 테스트 어댑터는 무료(실발송 안 함) | 실제 발송 계정 연결 시 발송량에 따라 과금(대부분 소량 무료 구간 있음) | 선택할 이메일 발송 서비스 가격표 |

**무료/유료 사용자별 비용이 어떻게 갈리는지**: 지금 구조에서 실제
돈이 드는 항목(장소 조회 API, 도보 경로, 서버, 결제 수수료, 이메일)은
전부 **로그인·결제 여부와 무관하게** 발생할 수 있다(예: 무료 체험
사용자도 코스를 만들면 도보 경로 계산 요청이 나간다). 즉 "유료
전환자만 비용이 든다"는 가정은 틀렸다 — 무료체험 1회 제한(로드맵
⑧)이 있는 이유가 여기 있다: 비용이 드는 기능을 무제한으로 공짜로
열어두지 않기 위해서다.

## 4. ChatGPT가 결정해야 할 것 — 선택지 정리

### 4-1. 브랜드·가격·기능 범위 (`src/landing.html` 충돌 — 가장 시급)

`src/landing.html`(기존 파일)은 브랜드 "별표털기", 서버 없는 단일
HTML, 9,900원 **한 번** 결제, AI 번역·일본어 회화팩·날씨·환율까지
포함한 제품을 설명한다. 이번 세션에서 만든 `src/design/landing.html`
+ 서버 백엔드는 브랜드 "travel hub", 실제 서버·로그인, 구독 가설(30일
단위), 장소 보관+코스 생성만 있는 제품이다. 자세한 비교표는
`docs/DESIGN_INTEGRATION_REPORT.md` 1-B-10 참고.

**선택지**:
- (A) "travel hub" 방향으로 완전히 전환하고 `src/landing.html`(구
  버전)은 폐기한다.
- (B) "별표털기" 한 번 결제 방향으로 되돌리고, 이번에 만든 서버·구독
  기능은 나중을 위해 남겨만 둔다(당장 안 씀).
- (C) 두 방향을 섞는다(예: 브랜드는 기존 유지, 가격 모델만 구독으로
  전환 등) — 이 경우 구체적으로 어느 요소를 유지·교체할지 다시
  정해야 한다.

이 결정에 따라 옛 마케팅 문서(`가격_판매전략.md`·`판매_SNS전략.md`·
`판매채널.md`·`홍보전략.md`)를 그대로 쓸지, `MARKETING_LAUNCH_PLAN.md`
(이번에 새로 쓴 문서)로 갈아탈지도 정해진다 — 옛 문서의 "복제를 막을
방법이 없으니 싸게 많이 판다" 전략은 서버가 없는 단일 HTML 파일
구조를 전제로 한 것이라, (A)나 (C)로 서버 기반 구조를 유지한다면 그
전제 자체가 안 맞을 수 있다(서버가 이용권을 확인하므로 파일을
복사해도 남의 이용권까지 복사되지는 않는다).

### 4-2. 가격 확정

`server/config.mjs`의 `9,900원/30일`, 자동결제 꺼짐 상태를 그대로
쓸지, 다른 금액·주기·한 번 결제 방식으로 바꿀지. 환경변수
(`PRICE_AMOUNT_KRW`/`PRICE_PERIOD_DAYS`/`PRICE_AUTO_RENEW`)로만
바꾸면 되므로 코드 수정은 필요 없다.

### 4-3. 도보 경로 계산 방식

지금의 무료 공개 OSRM 데모 서버를 실 서비스에서 계속 쓸 수 없다(3절
참고). 자체 OSRM 서버를 직접 운영할지, 유료 라우팅 API로 옮길지 —
둘 다 정기 비용이 든다는 전제로 결정 필요.

### 4-4. 179건 실사용 데이터 재검증 여부

2절에서 밝힌 대로 이번 세션엔 그 파일이 없어 재실행을 못 했다.
필요하면 사용자가 해당 Google Takeout 파일을 다시 올려줘야 한다.

### 4-5. 과거 커밋에 남은 개인정보 처리 여부

`docs/DESIGN_INTEGRATION_REPORT.md` 11절에 이미 정리됨(현재 파일은
고쳤으나 git 히스토리에는 남아 있음) — git 히스토리 재작성 여부는
아직 결정 안 됨.

## 5. 실제 전환에 필요한 계정·크리덴셜 — 한 번에 정리

아래 표는 `server/README.md`의 표를 그대로 옮긴 것이다(중복 유지
이유: 이 문서 하나만 봐도 결정에 필요한 전체 그림이 보이게 하기
위해서). **절대 채팅창에 실제 비밀키를 붙여넣지 말 것** — 실제 값은
서버가 실행될 환경(호스팅 서비스의 환경변수 설정 화면)에 직접
입력해야 한다.

| 필요한 것 | 환경변수 | 없으면 무슨 일이 생기나 |
|---|---|---|
| 서버 호스팅 | — | 지금은 로컬에서만 실행됨 |
| 장소 조회 API 키(Google Places 등) | `GOOGLE_PLACES_API_KEY` | 없으면 테스트 어댑터(가짜 좌표) 유지 |
| 결제대행사(PG) 가맹점 시크릿 | `PAYMENT_PG_SECRET` | 없으면 실제 결제 승인 불가 |
| 결제 웹훅 서명 검증용 비밀값 | `PAYMENT_WEBHOOK_SECRET` | 기본값은 테스트 전용 — 운영에 쓰면 안 됨 |
| 실제 이메일 발송 계정/키 | `EMAIL_API_KEY` | 없으면 로그인 코드 실제 발송 안 됨 |
| 확정 가격 | `PRICE_AMOUNT_KRW`, `PRICE_PERIOD_DAYS` | 지정 안 하면 가설값(9,900원/30일) 유지 |
| 자동결제 여부 | `PRICE_AUTO_RENEW` | 기본값 false — 켜려면 명시적 동의 UI 선행 필요 |
| (신규 결정 시) 도보 경로 API 키 또는 자체 OSRM 서버 주소 | 아직 코드에 환경변수로 안 빼둠 — 4-3 결정 후 추가 작업 필요 | 없으면 지금처럼 공개 데모 서버 계속 사용(운영 부적합) |

`GOOGLE_PLACES_API_KEY`·`PAYMENT_PG_SECRET` 둘 다 있어야 서버가
실제 모드로 전환된다 — 하나라도 없으면 항상 테스트 모드로 강제
전환된다("절반만 실제"인 상태로 조용히 운영되는 사고 방지).
