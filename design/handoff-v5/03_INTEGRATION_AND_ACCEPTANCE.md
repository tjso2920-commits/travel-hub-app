# 기능 통합 순서와 완료 기준

## 1. 현재 저장소부터 확인
원본 GitHub: https://github.com/tjso2920-commits/travel-hub-app
업로드 당시 프로젝트는 private/personal.html을 원본으로 삼고 build-sales로 src/index.html을 생성했다. private 파일은 Git 무시 대상일 수 있다. **현재 구조가 여전히 같은지 확인 후** 생성 파일만 단독 편집하는 실수를 피한다. 기존 승인 전후 기능을 유지한다. 오래된 테스트 경로로 실패한 이력이 있으므로 현재 baseline 실패와 새 회귀를 구분한다. 이번 패키지가 최신 기능 브랜치를 알고 있다고 가정하지 않는다.

## 2. 데이터 경계
현재 fixture: {id, city, name, category, area, memo, image}. 도시명은 표시값; 실서비스에서 국가가 다른 동명 도시를 합치지 않도록 안정된 city key + country + 좌표를 이용한다. 가져온 원문/사용자 메모를 보존한다. 장소 이름만으로 중복 제거하지 않는다. 안정된 place ID/지도 링크/좌표·주소를 종합하고 모호한 매칭은 확인 대상으로 남긴다.

실데이터는 현재 innerHTML 템플릿에 무가공 삽입하지 않는다. textContent/안전한 DOM 또는 escaping을 사용하고, 링크 스킴은 허용된 https/http 등으로 검증한다. 파일 크기/압축 해제 크기 제한, CSV 인용부호·줄바꿈·BOM·다국어·누락 열을 처리한다. ZIP을 지원한다고 표시하려면 ZIP 안의 지원 파일을 실제로 탐색/분석해야 한다. 미지원·부분실패·중복·성공 개수를 명확히 보고한다.

| 지점 | Claude 연결 |
|---|---|
| spots, cities | 실제 사용자 데이터 및 도시별 집계 |
| updateCity/chooseCity | 목적지 선택. 현재 GPS로 덮어쓰지 않음 |
| render/search/filters | 실제 지역과 유형, 길거나 빈 데이터 처리 |
| selected / route | 도시별 선택·일정 상태 및 저장. 새로고침 복원 |
| detail | 검증된 매장 이름/주소/전화/웹/지도/사진. 정보 없으면 없는 상태 |
| add/importDemo | 실제 파일 입력/진행/부분 성공/재시도. 샘플 결과를 성공처럼 재사용 금지 |
| nearby | 사용자의 명시적 동작 후 GPS 권한. 거절/실패 시 수동 출발지 |
| profile | 실제 프로필/통계. 샘플 Y를 사용자 계정이라고 표시하지 않음 |
| collection | 현재는 영역 스크롤만 구현. 완전한 앨범 관리 기능이라고 소개하지 않음 |

## 3. 순서
A. 실제 파일 분석 → 장소명/지도 링크 보존 → 도시별 카드 표시.
B. 장소 식별 정확도 검증 → 실제 사진·상세 정보 연결. 공급자 API 요금/사진 표시·저장 조건 확인. 사진 없으면 스타일에 맞는 빈 상태.
C. 동선과 이동 방법 → GPS는 필요할 때 요청. 직선거리와 실제 이동시간을 혼동하지 않기. 이동 방식별 경로 지원 범위를 검증.
D. 저장/복원·부분 오프라인·느린 네트워크 검증.
Google 로그인만으로 개인 저장 목록 자동 동기화, 목록 링크 하나로 안정적인 수입이 가능하다고 가정하지 않는다. 실제 API/권한 지원을 조사하고 실패 시 안내 가능한 경로를 제시한다.

## 4. 이탈 방지
첫 화면은 샘플로 즉시 체험 가능. 회원가입·GPS·날짜·숙소·API 키 입력을 모두 선행 조건으로 두지 않는다. 실서비스 사용자가 개발자용 API 키를 발급할 필요가 없는 구조로 설계한다. 미확인 장소는 별도 보관해 나중에 수정; 일부 실패로 성공한 데이터까지 숨기지 않는다. 파일 가져오기부터 첫 동선 완성까지 단계 수/시간/포기 지점을 관찰하되 개인 장소 원문을 분석 로그에 보내지 않는다.

## 5. 성능
샘플 사진 합계 402142 → 52302 bytes. 로컬 폰트 103144 bytes. 새 화면 HTML/CSS/JS+사진+폰트 185657 bytes(압축 전 파일 합계, 인증 응답 등 제외). 느린 회선 실측 결과가 아님.
사진·지도·외부 API를 160곳 모두 한 번에 요청하지 않는다. 목록 썸네일/상세 사진 분리, 화면 밖 사진 지연, 지도 SDK 필요 시 로딩. 사이트 접속/인증/TTFB와 앱 렌더링을 분리 측정한다. LCP 2.5초는 목표이지 현재 달성 수치가 아님.
개인 장소/확정 일정 저장은 앱 로직으로 구현. 사진/API 응답 저장은 제공 조건 확인 후 적용. preview sw.js를 원본 앱 서비스워커에 덮어쓰지 않는다.

## 6. 승인 기준
- 승인 fixture로 같은 viewport에서 전/후 화면 비교: 메인, 필터, 장소 상세, 도시 선택, 가져오기, 프로필, 선택바.
- 모바일 390px 및 좁은 320px, 데스크톱. 글자 200% 확대, 키보드 등장, safe-area, 모달 닫기/초점, 가로 넘침 확인.
- 실제 파일: 파일 선택→도시별 결과→카드→지도 링크 검증. 160개 전체가 실제 파일에 있을 때 그 수량으로 시험; fixture를 실제 성공이라고 보고하지 않음.
- 중복/동명이점/빈 좌표/잘못된 CSV/부분 실패/사진 없음/긴 한·영·일 장소명 검증.
- 후쿠오카에서 선택한 장소가 뉴욕 동선에 섞이지 않음. GPS 거절해도 목적지 탐색 가능.
- 기존 데이터 손실·기존 기능 회귀 여부 확인.
- 완료 보고: 변경 파일 / 실제 연결 완료 / 남은 데모 / 검증 결과와 한계 / 사용자 확인 필요 항목.
