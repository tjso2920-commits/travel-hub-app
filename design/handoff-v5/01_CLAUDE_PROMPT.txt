첨부한 travelhub_claude_handoff_v5 ZIP/폴더를 읽고, 기존 여행웹에 기능을 통합해 줘.

내 결정: ChatGPT가 만든 현재 디자인 그대로 사용한다. 너는 디자인을 재창작하는 담당이 아니라, 제공된 디자인 코드와 기존 실제 기능을 통합하는 담당이다.

먼저 00_START_HERE.md → 02_DESIGN_CONTRACT.md → 03_INTEGRATION_AND_ACCEPTANCE.md → 05_IMPORT_ONBOARDING_SPEC.md → approved-design/index.html, spots.css, spots.js 순서로 읽어라. 현재 개발 저장소의 AGENTS.md, 변경 중인 파일, 최신 구조도 확인하라. 첨부 classic.html은 오래된 참고 사본이므로 최신 소스를 덮어쓰지 마라.

승인한 사진첩 구성, 폰트, 색, 카드, 여백, 버튼, 검색창, 하단 메뉴를 유지하라. 내 실제 장소명이 길거나 사진이 없을 때는 기존 스타일 안에서 줄바꿈·빈 상태를 처리하라. 보안·접근성·기능 연결에 필요한 내부 변경은 하되, 눈에 띄는 디자인 변경이 필요하면 이유와 최소 대안을 보여줘라. 사용자가 결정하지 않은 디자인 개편을 하지 마라.

우선 완료할 범위:
1. 기존 CSV 가져오기 기능과 내가 제공한 실제 CSV/Takeout 저장 목록 ZIP의 구조를 확인한다. 현재 지원과 미지원 형식을 구분한다.
2. 별도 작업 브랜치에서 제공된 화면에 실제 저장 장소를 연결한다. 도시별 목록과 유형 필터를 실제 데이터에서 만든다. 선택한 여행지와 GPS 위치는 별도 상태다.
3. 첫 결과는 '실제 파일 가져오기 → 확인 가능한 장소 정리 → 여행지 선택 → 내가 저장한 장소 카드 표시'까지다. 일부 미확인 장소 때문에 전체 가져오기를 막지 마라.
4. 지금은 텍스트·분류·실제 지도 링크의 정확성을 먼저 검증한다. 실제 사진이 없으면 명확한 빈 상태로 표시하고, 샘플 사진을 실제 매장 사진인 것처럼 연결하지 마라.
5. 개인정보를 공개 Git 저장소·테스트 fixture·로그에 커밋하지 마라. 기존 사용자 데이터와 localStorage 키를 보존하고 필요한 변경은 명시적 마이그레이션으로 처리하라.
6. 모바일 폭, 긴 한국어/영어/일본어 장소명, 빈 결과, 잘못된 CSV, 중복, 일부 실패를 확인하라. 동일 fixture/화면 크기/폰트 로딩 조건으로 승인 화면과 통합 화면을 비교하라.
7. 변경 파일, 실제 작동하는 기능, 남은 샘플, 수행한 테스트/미수행 테스트를 구분해 보고하라. 공개 배포는 별도 요청 전 하지 마라.

첫 응답에서는 읽은 기준, 현재 저장소 상태, 변경 예정 파일과 첫 구현 범위를 짧게 알려주고, 필요한 자료가 있으면 실제로 부족한 것만 요청하라. 실제 CSV가 아직 없더라도 코드 분석·어댑터 준비 등 가능한 작업은 진행하라. 없는 API나 자동 동기화 기능을 있다고 가정하지 마라.
